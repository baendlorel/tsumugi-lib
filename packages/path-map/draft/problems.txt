# PathMap 源码审查问题清单

审查范围：src/index.ts
审查基准：只读分析，不做修改

────────────────────────────────────────────
## 严重 (必须修)

### 1. `get([])` 返回根 Map 对象
- 位置：get() 方法
- 描述：keys 为空数组时 for 循环不执行，cur 保持为 this.map（根 Map），返回 `cur as V`
- 结果：调用者得到一个内部 Map 引用，破坏了封装
- 建议：开头加 `if (keys.length === 0) return undefined`

### 2. `set([])` 在根 Map 上设 undefined 键
- 位置：set() 方法
- 描述：`keys.length - 1 = -1`，循环不执行，执行 `cur.set(keys[-1], value)` 即 `cur.set(undefined, value)`
- 结果：非预期的键被写入
- 建议：开头加 `if (keys.length === 0) throw new TypeError(...)`

### 3. `delete([])` 删除根 Map 的 undefined 键
- 位置：delete() 方法
- 描述：同上，`cur.delete(keys[-1])` 即 `cur.delete(undefined)`
- 结果：可能误删其他逻辑写入的 undefined 键
- 建议：开头加 `if (keys.length === 0) return`

### 4. `has([])` 返回 false（这个是对的），但 `has([mid])` 对中间节点误判
- 位置：has() 方法（暂缺失，如实现则需注意）
- 描述：如果 `['a','b','c']` 被 set 过，`has(['a','b'])` 会走到 b 这个内部 Map，循环结束返回 true
- 结果：用户以为中间路径有值，实际只是自动创建的内部节点
- 建议：循环中如果 cur 是 Map 且 i === length-1，应返回 false

────────────────────────────────────────────
## 中等

### 5. `get` 方法声明了自己的 `<V>` 泛型遮蔽类泛型
- 位置：`get<V = any>(keys: K): V | undefined`
- 描述：重新声明 `<V>` 让调用者可以 `map.get<number>(keys)`，但跟类的 `V` 可能不一致
- 建议：去掉方法上的泛型，直接用 `get(keys: K): V | undefined`

### 6. 没有 `has()` 方法
- 描述：README 里写了 has() 但类上未实现
- 建议：按需添加

### 7. `forEach` 回调第三个参数类型承诺与运行时不一致
- 位置：`forEach(callbackfn: (value: V, keys: K, map: PathMap<K, V>) => void, ...)`
- 描述：类型签名说第三个 map 是 PathMap 实例，但 iterate 里传的是内部 `Map`（`callbackfn.call(thisArg, value, nextKey, map)` 中的 map 是当前层的子 Map）
- 建议：要么改类型为 `Map<any, any>`，要么改 iterate 传 PathMap

────────────────────────────────────────────
## 低

### 8. `[Symbol.toStringTag]` 不是 getter
- 位置：`[Symbol.toStringTag]() { return 'PathMap'; }`
- 描述：应使用 getter 语法 `get [Symbol.toStringTag]()`，当前写法在某些环境可能不生效
- 建议：改为 getter

### 9. 拼写：interalMaps → internalMaps
- 位置：clear/iterate/entries 函数参数名
- 描述：interal 是拼写错误，应为 internal
- 建议：不影响功能，代码洁癖可改

### 10. 没有 size 属性
- 描述：标准 Map 有 size，PathMap 没有
- 建议：按需添加，需遍历整棵树

### 11. delete 后不清理空中间节点
- 描述：删除叶子后，如果中间 Map 变空，仍留在父 Map 中
- 建议：标准 Map 也是这样，不修也可以
