[中-6] 子类覆写 @Cache 方法的行为
  现象（运行时验证）：
    - 子类用【相同 id】覆写：`new` 时抛 `Duplicate cache id "…" for the same instance.`；
      这是最自然的覆写写法（还能让父类的 @SubCache 继续指向子类实现），却直接报错。
    - 子类用【不同 id】覆写：父、子两个 cacher 都会注册，initializeDecoratedCaches
      会把两个 getter 都执行一遍（父类那个只能通过 super 访问，往往是一次多余的请求）。
  现状：README 已说明当前行为（同 id 抛错、无装饰器覆写静默跳过），
        但尚未确立"同 id 时子类替换父类 cacher"的设计方案与实现。

[文档-2] 注释与行为不符 / 遗留问题
  a. cacher.ts `initialized` getter JSDoc "Checks if the cache is empty"，语义相反
     （应为"Returns true after the first successful load"）。
  b. cacher.ts `setThis` JSDoc "If the cache is empty, it will trigger a reload."，
     实际不会触发 reload。
  c. cacher.ts `get()` JSDoc "it will trigger the initialization"，
     实际是调用 reload() 并等待其结果（"trigger a reload and await it"）。
  d. cacher.ts `getSub` 中的 `current !== empty` 判断恒真（await this.get() 返回后
     cache 不可能是 empty），`const parent = current` 是无意义的别名，
     "Initialized cache won't be empty." 注释也可删除。
  e. mapper 能否 async 前后矛盾：derive JSDoc 写 "pure sync … called without `await`"，
     但 getSub 实际调用了 `await sub.fn.call(…)`；而且 @SubCache 的装饰器方法本身必须
     async 才能通过类型检查（高-2）。需要统一说法：mapper 是 sync，@SubCache 方法的
     async 是外层包装，内部逻辑须同步（或正式支持 async mapper 并更新文档）。
  f. cacher.ts `getOrDerive` 参数名 `pureMapFn` 与 JSDoc `@param pureMapper` 不一致。
  g. decorator.ts `SubCache` 函数签名为 `(fromId: string, subId: string)`（两个必填参数），
     但 examples/index.ts 中所有 @SubCache 调用均只传一个参数（如 `@SubCache('a')`），
     导致 subId 在运行时为 undefined。examples/ 不在 tsconfig include 范围内，tsc 不报错，
     但当同一 fromId 有多个 @SubCache 时，所有派生值共用 undefined 键，后注册者会被静默覆盖。
     建议：在 SubCache 实现中以 `_context.name`（方法名）作为 subId 的默认值，
     或在 examples/ 中补全第二参数，并把 examples/ 加入 tsconfig include。

[测试-1] tests/index.test.ts 基于旧 API，需按当前实现重写
  主要失败原因：
    - `get()` 现为 async，旧测试未 await，断言比较的是 Promise 对象而非值。
    - `expect(() => cacher.get()).toThrow(…)` 无法捕捉 async 函数的 rejection。
    - `reload()` 恒返回 Promise；旧测试 `expect(sync.reload()).toBe(3)` 对同步 getter 也失败。
    - `isInitialized` 已改为 `initialized`。
    - `getSync`、同步读取语义均已删除。
  建议：完整重写 tests/index.test.ts，get / reload / loading / getSub / getOrDerive
        均使用 await，并将装饰器测试从 examples/ 迁移进 vitest（目前不进 CI）。

[测试-2] examples/index.ts 装饰器用例不进 CI
  已覆盖场景：同类 @Cache + @SubCache、@SubCache 写在 @Cache 前、父 @Cache + 子 @SubCache、
              父 @SubCache + 子 @Cache、每实例隔离、同类重复 id、无 @Cache 的 @SubCache、
              @SubCache / getSub 的 TTL、getter 同步抛错后重试（中-1）、

五、低
------------------------------------------------------------------

[低-1] implements/old1.ts 是旧版实现（含 clear()/clearAfterPromise 方案），仍被 tsconfig include
      编译，与现行 API 冲突且无说明；建议移出 src 范围或在文件头标注为历史草稿。
[低-2] package.json：`scripts.test` 使用 `clear && vitest`（非交互/CI 环境下 clear 可能报错，
      且 vitest 默认进入 watch 模式）；缺少 `sideEffects: false`；
      无 `engines` 字段（使用了 performance.now、WeakKey 类型）。
[低-3] Cacher 的 private 成员用 `/* @internal */` + stripInternal 从 .d.ts 中剥除，
      发布后的 Cacher 类型变为无私有成员的结构类型，丧失名义性。
      另：runGetter 漏了 `/* @internal */`，构建出的 .d.ts 里只剩孤零零的 `private runGetter;`。
[低-4] getOrDerive 在 name 已存在但 mapper 不同时，静默忽略新 mapper（只在首次登记时生效）。
      README 现已说明此行为，但 JSDoc 尚未更新。
[低-5] getSub 以 Object.is 判断父值是否变化：getter 每次返回新对象（常见的 fetch().json()）时，
      每次刷新后派生值都会重算，没有可选的深比较 / 自定义 equals 参数。
[低-6] 泛型顺序 `Cacher<Subs, T>`：TS 不支持部分推断，只要显式写了 Subs，T 就退化为 any。
      类型验证：`new Cacher<{ doubled: number }>(async () => 'str', 1000)` 之后 get() 为 any，
      `derive('doubled', x => x.not_exist)` 也能编译通过。
      建议：将 T 放到第一位，或让 derive / getSub 各自推断子类型，与 Subs 解耦。
